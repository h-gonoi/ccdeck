# ccdeck mobile — 仕様

PC で走っている Claude Code / Codex セッションを、同じ Wi-Fi にいるスマホから見て、打てるようにする。

ccdeck の値打ちは「**手が空いたセッションに気づける**」ことにある。スマホ側もそこを主役にする。
一覧と通知が先、ターミナルは後。**軽さが最優先**という母体の方針は、こちらにも効かせる。

## いまどこまでできているか

| | 状態 |
|---|---|
| サーバーの `--lan` とトークン認証、端末の登録・失効 | **実装済み** |
| PC 画面のペアリング（コード発行・端末一覧） | **実装済み** |
| スナップショット（`attach { mode:'snapshot' }`） | **実装済み** |
| 画面サイズの所有権（`claimSize` / `releaseSize`） | **実装済み** |
| スマホアプリ M1（ペアリング・一覧・snapshot の読み取り） | **実装済み** |
| 会話モード（`attach { mode:'chat' }`。transcript を発言の並びで返す） | **実装済み** |
| スマホからのキー入力・承認の近道・キーバー（M2） | **実装済み**（サイズ所有権の操作は未実装） |
| 執事（見立て → 承認 → 手順を渡す）。PC とスマホの両方から | **実装済み** |
| push 通知 | M3（未実装） |
| TLS と証明書ピン留め | M4（未実装） |

## これは何ではないか

| やらないこと | 理由 |
|---|---|
| 外出先（LAN の外）から繋ぐ | 今回は LAN 限定と決めた。穴を開ける判断は別途 |
| 外部セッション（Cursor の内蔵ターミナル等）への入力 | PTY を持っているのは向こう。横取りすると両方壊れる（母体と同じ理由） |
| スマホでの git 操作・ファイル編集 | PC 側の機能。小さい画面でやる必然がない |
| スマホをサーバーにする | 常駐コストが跳ねる |

## 決めたこと

| 項目 | 決定 |
|---|---|
| 届かせ方 | **同じ Wi-Fi の中だけ。** サーバーを LAN に出し、端末ごとのトークンで守る |
| アプリ | **Expo (React Native)。** iOS / Android 両方 |
| 操作の範囲 | **フルターミナル。** 全キー入力を中継する |
| 置き場所 | ccdeck 本体と同居（`mobile/`） |

## 全体像

```
  iPhone / Android                         Mac
  ┌────────────────┐                    ┌──────────────────────────┐
  │ Expo アプリ     │                    │ ccdeck server            │
  │  一覧・状態     │◀── WS /ws ────────▶│  SessionManager → PTY    │
  │  M1: 画面を読む │    REST /api       │  headless xterm（判定）  │
  │  M2: 入力       │                    │  auth / devices          │
  └────────────────┘   同じ LAN だけ     └──────────────────────────┘
          ▲                                          │
          │                                          │ outbound
          └────── Expo Push ◀── APNs / FCM ◀─────────┘
                  （通知は外でも届く。開けるのは LAN の中だけ）
```

## 1. 接続と認証

### バインド先は既定を変えない

サーバーは今まで通り `127.0.0.1` で上がる。**LAN に出すのは明示したときだけ。**

```sh
ccdeck start            # 127.0.0.1:7788（今まで通り）
ccdeck start --lan      # 0.0.0.0:7788 + トークン必須
```

`--lan` を付けた起動では、ターミナルに待ち受けアドレスと警告を出す。何が起きているかを黙らせない。

```
ccdeck → http://192.168.11.146:7788  (LAN に出しています)
  ⚠ 同じ Wi-Fi にいる誰でもここに到達できます。
    繋げるのは登録した端末だけです。登録は Mac の画面から行ってください。
  記録: /Users/xxx/.ccdeck/audit.log
```

### ループバックは素通し、それ以外はトークン

| 接続元 | 扱い |
|---|---|
| `127.0.0.1` / `::1` | 認証なし。既存の PC 画面を壊さないため |
| それ以外 | `Authorization: Bearer <device token>` 必須。無ければ 401 |

WebSocket も同じ。React Native の `WebSocket` は第3引数でヘッダを渡せるのでヘッダを正とし、
ブラウザから繋ぐ場合のために `?token=` も受ける（**アクセスログに残るので非推奨**と明記する）。

### ペアリング（実装済み）

PC 画面の左下「スマホ」に、待ち受けアドレスと 6 桁コードを出す。
スマホ側はアドレスとコードを打ち込む。

- コードは **120 秒で失効**、**1 回使い切り**、同時に生きているのは常にひとつ。
  外し続けると **5 回でコードごと捨てる**（総当たり対策）。
- `POST /api/pair { code, name, platform }` → `{ device, token }`
- トークンは 32 バイト乱数（base64url）。サーバーは **SHA-256 のハッシュだけ**を
  `~/.ccdeck/devices.json`（0600）に持つ。平文は端末側の SecureStore にだけ残る。
- 端末一覧と失効は PC 画面から。**失効はその場で効く**（次のリクエストから 401）。

> **QR は後回しにした。** 依存をひとつ増やす価値が、
> 「6 桁とアドレスを一度打つ」手間に見合わないため。入れるときは
> `editor.js` と同じく、ペアリング画面を開いたときだけ動的 import する。

`/api/health` は `hostname` も返す。M1 は入力した IP アドレスを SecureStore に保存する。
DHCP 変更時の **hostname → 最後に繋がった IP** のフォールバックは今後の課題。

## 2. プロトコル

既存のものをそのまま使う。**モバイル専用の API は増やさない**。増やすと二重管理になる。

### REST（既存・変更なし）

`/api/sessions`（GET / POST / DELETE）、`/api/external`、`/api/git/*`、`/api/files/*`、`/api/projects`

### REST（追加）

| メソッド | パス | 用途 | 誰から |
|---|---|---|---|
| GET | `/api/health` | version・buildId・hostname・待ち受け先・capabilities | 誰でも（トークン不要） |
| POST | `/api/pair` | ペアリングコードをトークンに交換 | 誰でも（コードが要る） |
| GET / POST / DELETE | `/api/pair/code` | コードの確認・発行・取り消し | ループバックのみ |
| GET | `/api/devices` | 繋いだ端末の一覧 | ループバックのみ |
| DELETE | `/api/devices/:id` | 失効 | ループバックのみ |
| POST | `/api/push/register` | Expo push トークンの登録 | 認証済み端末 |

`/api/health` だけトークン不要にするのは、アプリが「繋がるか」「版が合うか」を
ペアリング前に確かめられるようにするため。返すのは版と機能一覧だけで、セッション情報は含めない。

### WebSocket（既存）

| 向き | type | 備考 |
|---|---|---|
| ← | `hello` | `buildId`。版が変わっていたら画面は自力でリロードする |
| ← | `sessions` / `external` | 一覧まるごと |
| ← | `replay` / `output` | PC 向けの生出力 |
| → | `attach` / `detach` / `input` / `resize` / `read` | |

### WebSocket（追加）

| 向き | type | 内容 |
|---|---|---|
| → | `attach` | `{ id, mode: 'replay' \| 'snapshot' \| 'text' }` を受けるよう拡張 |
| ← | `snapshot` | `{ id, cols, rows }` に `data`（ANSI）か `text`（素の文字）が付く |
| → | `claimSize` | `{ id, cols, rows }` 画面サイズの持ち主を奪う |
| → | `releaseSize` | `{ id }` 返す |
| ← | `sizeOwner` | `{ id, mine: bool, cols, rows }` 持ち主が変わったとき |
| ↔ | `ping` / `pong` | アプリ層の生存確認（20 秒ごと、10 秒無応答で張り直す） |

セッションの JSON には `cols` / `rows` が入る。所有権は接続ごとに異なるため、
セッション JSON ではなく `sizeOwner` イベントで知らせる。

## 3. 画面サイズの取り合い（ここが一番の勘所）

PTY のサイズは**セッションにひとつしかない**。PC が 120×34、スマホが 45×22 で、
両方が `resize` を送れば奪い合いになり、Claude Code の TUI は描き直すたびに崩れる。
母体の「replay はサイズを確定させてから流す」と同じ根の問題で、放っておくと
**スマホが繋いだ瞬間に PC の画面が 45 桁に潰れる。**

### 決めごと

1. サイズの持ち主は、セッションごとに**ちょうど 1 クライアント**。
2. 既定の持ち主は**最初に attach したクライアント**（ふつうは PC）。
3. 持ち主が detach したら、残っている中の最初のひとつへ移る。誰も居なければ持ち主なし（サイズは最後の値のまま）。
4. **止めるのは覗き見だけ。** `attach { mode: 'snapshot' | 'text' | 'chat' }` で繋いでいる相手
   （＝スマホ）の `resize` は、持ち主でなければ黙って捨てる。エラーにはしない
   （画面を回すたびに叱っても仕方がない）。
   **画面いっぱいで見ている相手（PC）の `resize` は常に通し、送り主が持ち主になる。**
   PC どうしにも「持ち主でなければ捨てる」を適用すると、別ウィンドウが持ち主のまま残ったとき、
   手元の窓から桁数を直せなくなる（実際にそうなった）。
5. `claimSize` で明示的に奪える。奪われた側にはトーストで伝える。
6. **スマホは既定で奪わない。**「この画面に合わせる」を押したときだけ奪う。
7. PC 側は、奪われても**手前に居るときだけ**取り返す。席を外している間はスマホの取り分が残る。

### 奪わないときの見せ方

| 状況 | 見せ方 |
|---|---|
| 幅が入る | 持ち主の桁数（例 120）が入るところまでフォントを縮める |
| 縮めても入らない | 下限 6px で止め、**横スクロール**にする |
| 横向き | だいたい入る。回転を促す小さな案内を一度だけ出す |

ピンチで拡大縮小できる。奪えば読みやすくなるが PC 側が崩れる、という取引を
その場で選べるようにする。黙って最適化しない。

## 4. 復帰とスナップショット

iOS はバックグラウンドで WebSocket を切る。**復帰のたびに 512KB の replay を流すのは重い。**

判定用に持っている headless xterm（`sessions.js`）をそのまま使う。`scrollback: 0` なので、
`@xterm/addon-serialize` に通せば「**いま見えている画面ちょうど**」が数 KB の ANSI で出る。

| クライアント | attach の mode | 流れるもの |
|---|---|---|
| PC（既存） | `replay` | 生出力 512KB（今まで通り。既定を変えない） |
| スマホ（M1・色を出さない） | `text` | 今の画面の文字だけ |
| スマホ（M2・xterm.js） | `snapshot` | 今の画面を ANSI で |

復帰の手順は **WS 張り直し → `attach { mode:'text' }`（M1）**。
snapshot / text の購読者には生の `output` を流さず、出力があったときに最大 2 回/秒へ間引いた
新しい画面を送る。切れている間の出力は追わない。現在画面だけで追いつく。

### ANSI を送って向こうで剥がしてはいけない

色の要らない相手に ANSI を送り、受け手で装飾を落とすと、
**カーソル移動で作られた横の間隔まで消える。**
`Claude Code   v2.1.231` が `Claude Codev2.1.231` になり、枠も表もずれる。

桁数を知っていて、正しく組めるのはサーバー側だけ（判定用の headless xterm がある）。
だから色の要らない相手には `text` を送る。`server/sessions.js` の `screenText()` が
画面バッファを行ごとに読んで組み立てている。**受け手で ANSI を剥がす実装に戻さないこと。**

> スクロールバックはこの方式では見られない。必要になったら別途 `history` を足す（未決）。

## 5. スマホの画面

### 一覧（最初に出る画面）

母体と同じ信号の使い方を守る。**琥珀は「あなたの番です」にだけ。**

```
ccdeck                          ⟳
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
│ quiz-app              要対応  ← 琥珀の縦バー
│ feat-admin-api · 2分前
├────────────────────────────────
│ ccdeck                実行中  ← 控えめな緑
│ main · たった今
├────────────────────────────────
│ ai-coach-science      待機
│ feat/material · 18分前
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
他で動いている 2                 ← 表示だけ。打てない
```

- 並びは PC と同じ（要対応 → 未読 → それ以外）。
- 引っ張って更新。ただし WS が繋がっていれば自動で来る。
- カードで囲まない。区切りは余白と線。角丸 3px。母体のデザインの決めごとをそのまま使う。

### 現在画面（M1）

`text` モードで受け取り、等幅のプレーンテキストとして縦横にスクロールして読む。
トークンや WebSocket は React Native 側だけが持つ。

### いまの画面構成（M2）

画面は「部屋」。1 セッション＝1 人の住人で、部屋の絵は WebView の canvas（`mobile/scene/scene.html`）が描き、
操作はすべて React Native のネイティブ部品で行う（canvas に自前で描いたボタンはタップ判定・スクロール・IME が弱かった）。

| 画面 | 中身 |
|---|---|
| Lobby | 部屋の絵＋住人一覧＋よそで動いているもの。住人を叩くと Room へ |
| Room | 会話（`chat` モード）を読み、下の欄から話しかける。キーバー（Esc / Tab / ↑↓←→ / ⏎ / ^C）。呼ばれていれば `text` モードに切り替えて問いの箱を切り出し、承認 ⏎ / 1 2 3 / Esc を出す |
| Butler | 執事。見立てを頼む・提案を承認する・進み具合を見る |

サーバーは 1 つの繋がりにつきセッション 1 本しか attach を受けないので、
`chat` と `text` を切り替えるときは detach してから付け直す（`deck.ts` の `watch(id, mode)`）。
文章は**貼り付け（bracketed paste）として送り、Enter は少し置いてから**送る。
ひとかたまりで送ると改行が送信と取られたり、送信されなかったりする。

`attach { mode:'chat' }` を知らない古いサーバーは `replay` を返してくる。
そのときは会話を諦めて `text` に切り替える（`chatOk === false`）。

### ターミナル（M2）

WebView に xterm.js を積む。**WebSocket は React Native 側が持ち、WebView は描画専用**にする。

```
RN ──┬── WebSocket（認証・再接続・全セッション分）
     └── postMessage ──▶ WebView（xterm.js。1 セッション分を描くだけ）
                      ◀── キー入力
```

| 向き | メッセージ |
|---|---|
| RN → WebView | `{t:'out', d}` `{t:'snap', d, cols, rows}` `{t:'fit', width, scale}` |
| WebView → RN | `{t:'key', d}` `{t:'size', cols, rows}` `{t:'ready'}` |

こうする理由は三つ。**トークンを WebView に渡さずに済む**。再接続の面倒が 1 か所に集まる。
画面を離れても購読を保てる。

xterm.js と CSS は HTML に**インラインで埋める**。CDN を引かない（オフラインで動く・依存が増えない）。

### キーバー

ソフトキーボードの上に常設する。

```
┌──────────────────────────────────────┐
│ Esc │ Tab │ Ctrl │ ↑ │ ↓ │ ← │ → │ ⌥ │
└──────────────────────────────────────┘
```

- `Ctrl` は**ラッチ**（次の 1 打だけ修飾）。`Ctrl` → `C` で中断。
- IME は**確定したときだけ送る**。変換中の文字は送らない。
- 貼り付け対応。

### 承認の近道

状態が `attention` のときだけ、キーバーの上にもう一段出す。

```
┌──────────────────────────────────────┐
│  承認 (Enter)  │  拒否 (Esc)  │ 1 2 3 │
└──────────────────────────────────────┘
```

フルターミナルであっても、**外出中にやりたいことの九割はこれ**。届く場所に置く。

## 6. 通知（M3）

「気づける」がこのアプリの主目的。ここを外すと作る意味がない。

- 送るのは **`running` → `attention`** と **`running` → `idle`**（＝自分の番が回ってきた瞬間）だけ。
  PC 側の `notify()` と同じ判断を使い、判定を二重に持たない。
- 経路は Mac → Expo Push → APNs/FCM → 端末。**Mac から外向きの通信だけで済む**（受けの穴は開けない）。
- **通知は LAN の外でも届く。ただし開けるのは同じ Wi-Fi にいるときだけ。**
  これは LAN 限定を選んだ帰結。アプリの設定画面にそう書いておく。
- 本文の既定は `ccdeck · 要対応 1 件`。**プロジェクト名は出さない。**
  Expo と Apple/Google を通るため。詳しく出すのはオプトインにする。
- **WS が繋がっている間は push を送らない。** アプリが前面にいるのに二重に鳴らさない。
- 同じセッションからの通知は 60 秒に 1 回まで。

## 7. セキュリティ

**脅威モデル：同じ Wi-Fi にいる他人。** カフェや来客のいるオフィスを想定する。

ccdeck は PTY を作れる。**素で LAN に出すことは、その Wi-Fi にいる全員に
シェルを配ることと同じ**になる。だから次を仕様に含める。

| 守り | 中身 |
|---|---|
| 既定は閉じたまま | `--lan` を明示しない限り `127.0.0.1`。LAN 起動時はアドレスと警告を出す |
| コマンドを固定 | `POST /api/sessions` は `command` を受けず、`agent` を `claude` / `codex` の固定コマンドへ変換する |
| 全 API にトークン | git も files も同じ扱い。M1 アプリは読み取りだけだが、サーバーの認可境界は共通 |
| 端末ごとの鍵 | 失効は 1 台ずつ。共有パスワードにしない |
| 記録 | LAN からのセッション作成・kill・入力の開始を `~/.ccdeck/audit.log` に 1 行ずつ |

### 平文で流れることを隠さない

素の HTTP で流すので、**トークンも打鍵も同じ LAN からは覗ける**。
`--tls`（自己署名 + QR に指紋を載せてアプリでピン留め）を M4 で足すが、
それまでは「信頼できる LAN でだけ使うもの」として README に書く。できないことを書かない。

| `web/` | ペアリングコード、端末一覧、サイズを誰が持っているかの表示 |

## 9. 段階

| | 目標 | 終わりの合図 |
|---|---|---|
| **M1 読める（完了）** | 一覧・状態・スナップショット表示 | スマホで「どれが自分の番か」が判る |
| **M2 打てる（完了）** | 入力・キーバー・承認の近道 | スマホから承認して先へ進められる（サイズ所有権の操作は残） |
| **M3 気づける** | Expo Push | 画面を見ていなくても呼ばれる |
| **M4 守る** | TLS + ピン留め、端末失効 UI、監査ログ | 信頼しきれない LAN でも使える |

M1 の前提だったサーバー側の認証（`--lan`・トークン・端末の登録と失効・記録）は**入れ終わっている**。
**認証のない状態で LAN に出す版は、途中経過であっても作らない。**

---

## 10. 変更時に確認すること

母体の流儀に合わせ、触ったら最低限これを見る。

1. **スマホが繋いでも PC の TUI が潰れないこと**（サイズ所有権が効いている）
2. 機内モードにして戻したとき、スナップショットで画面が復元されること
3. トークンなしの LAN からのリクエストが 401 で落ちること。ループバックは素通しのままであること
4. LAN から `command` を指定しても `claude` 以外が起動しないこと
5. 承認待ちの通知が 1 セッションにつき 1 回で、フラップしないこと
6. `--lan` を付けない起動で、外から一切繋がらないこと
7. PC 側の 12 枠表示が今まで通りであること

## 11. 決めていないこと

- スクロールバックをスマホから遡れるようにするか（今はスナップショットのみ）
- Android での `*.local` 解決（端末差がある。IP 直指定で逃げる）
- Mac が複数あるときの繋ぎ替え
- 外出先からの接続（今回の非目的。やるなら Tailscale か Cloudflare Tunnel を後付けする）
