# ccdeck

複数の Claude Code / Codex セッションを一画面で束ねるための、軽いデッキ。
Cursor のような汎用 IDE を複数ウィンドウ開かずに、並行作業の「今どれが自分の番か」を見えるようにするために作った。

## 何をするもの

- 走らせている Claude Code / Codex セッションを全部リストで並べ、**手が空いたものを琥珀色で知らせる**
- ブラウザを閉じてもセッションは死なない（PTY はサーバー側が持つ）
- サーバーを入れ替えても、**次の起動で会話の続きから同じ枠に戻る**
- git の差分確認・ステージ・コミット・push
- 変更ファイルをその場で開いて直せる簡易エディタ

各 agent の CLI をそのまま擬似端末で動かしているので、スラッシュコマンドや権限プロンプトは通常どおり使える。

## メニューバー

`~/Applications/ccdeck.app` がメニューバーに常駐する。ログイン時に自動で立ち上がり、
ccdeck サーバーが止まっていれば起動時に一度だけ立ち上げてくれる。

| 表示 | 意味 |
|------|------|
| **● 3**（琥珀） | 3 件が自分の入力を待っている |
| ▶ 2（グレー） | 2 件が作業中 |
| cc（グレー） | 待機のみ、または稼働なし |

クリックすると全セッションが状態つきで並ぶ。ccdeck のものを選べばウィンドウが開き、
他のターミナルのものを選べばそのウィンドウが前に出る。

止めたいときはメニューから「終了」。自動起動をやめるなら:

```sh
launchctl unload ~/Library/LaunchAgents/dev.ccdeck.menubar.plist
rm ~/Library/LaunchAgents/dev.ccdeck.menubar.plist
```

ソースは `menubar/main.swift`。作り直すときは:

```sh
cd menubar && swiftc -O -o ccdeckbar main.swift -framework Cocoa
cp ccdeckbar ~/Applications/ccdeck.app/Contents/MacOS/ccdeck
codesign --force --deep --sign - ~/Applications/ccdeck.app
```

## 使い方

```sh
ccdeck            # サーバーを起動して独立ウィンドウを開く
ccdeck start      # サーバーだけ起動
ccdeck status     # 稼働状況とセッション数
ccdeck stop       # 停止（走っているセッションが居れば本数を出して聞く）
ccdeck stop --force  # 聞かずに停止
ccdeck log        # サーバーログを追う
```

左の一覧からプロジェクトをクリックすると、そこで既定の Claude Code が立ち上がる。
同じプロジェクトで2本目を立てたいときは ⌘ を押しながらクリック。

左上の **＋** は agent（Claude Code / Codex）とプロジェクトを選んでから立てる。
agent の既定は Claude Code。打ち込めば名前とパスで絞り込め、
↑↓ と Enter で決まる。開いた直後に当たっているのは、いま打っているセッションの場所なので、
`⌘N` → `Enter` はこれまでどおり「今の場所でもう一本」になる。

### Agent を引き継ぐ

チャット画面上部の **Claude Code / Codex** ボタンで agent を切り替えられる。
反対側を初めて押すと、同じプロジェクトで新しいセッションを立て、元 agent のローカル transcript を
共通テキストへ変換して最初のプロンプトに渡す。取得できない場合は現在のターミナル画面を使う。
作成後は同じボタンで両セッションを往復できる。

各サービス固有の内部状態をそのまま再開するのではなく、発言と主要なツール履歴を相手 agent が読める形へ
変換する方式である。同じ作業ディレクトリのファイル・git 状態も残るので、上限到達などで元 agent が
応答できない場合にも使える。

サーバー再起動などで同じ agent の会話を戻す場合は、保存済みの session ID を固定形式の
`claude --resume <id>` / `codex resume <id>` に渡してネイティブの会話履歴を復元できる。
API は UUID 形式の ID だけを受け付け、任意のコマンド文字列には展開しない。

**最近使ったプロジェクトは上に寄せる。** ＋ の一覧でも左のプロジェクト一覧でも、
直近に立てた場所が先頭に来て、それ以外とは細い線で区切られる。記録は
`~/.ccdeck/recent.json`（セッションを立てた時刻だけ、40件まで）。

### キーボード

| キー | 動作 |
|------|------|
| ⌘N | プロジェクトを選んで立てる（そのまま Enter で今の場所） |
| ⌘J | **次に自分の手を待っているセッションへ飛ぶ** |
| ⌘1〜9 | セッションを番号で切り替え |
| ⌘E | 走っているセッションを全部並べる／1つに戻す |
| ⌘クリック | そのセッションを並びに足す・外す |
| ⌘B | サイドバーを畳む／戻す |
| ⌘G | git パネルの開閉 |
| ⌘S | エディタで開いているファイルを保存 |

### 並べて見る

`⌘E`（または「並べる」）で、走っているセッションを一画面に敷き詰める。**最大12枠**。
枠数に応じて列が変わり（〜2枠は2列、〜9枠は3列、〜12枠は4列）、
狭くなった枠では文字を自動で詰めるので、12分割でも Claude Code の TUI は崩れない。

- 枠をクリックすると、そこがキー入力の行き先になる（枠の縁が琥珀になる）
- サイドバーを `⌘クリック` すると、その1本だけを並びに足したり外したりできる
- **サイドバーからターミナル領域へドラッグ**しても枠に入る。既にある枠の上に落とせばその位置に割り込み、空いている所に落とせば末尾に付く
- **枠のヘッダを掴んでドラッグ**すると枠の順番を入れ替えられる
- 枠の `×` でその枠だけ閉じる（セッションは生きたまま）
- `⌘B` でサイドバーを畳めば、画面を丸ごとターミナルに使える
- どの枠を並べていたかは覚えているので、開き直すと同じ並びに戻る

`⌘J` は並べている最中なら枠はそのままに、入力先だけを次の要対応へ移す。

### いらなくなったセッションを終わらせる

やり方は2つある。

**行の `×`** — 常に薄く見えていて、行にマウスを乗せると濃くなる。
見た目は小さいが当たり判定は 24×24px 取ってあるので、狙いを外しにくい。
押すと行の中で一度だけ確認を挟む（作業中のものは「作業中です。終了？」と出る）。
モーダルは出さないので、間違って押しても「やめる」で戻れる。

**行を右クリック** — 小さなボタンを狙う必要がない。行のどこで押しても操作盤が出る。

```
同じ場所-1
─────────────────────
大きく開く
並べて表示に足す
このセッションを終了
同じ場所の他 2 本を終了      ← 押すと「本当に 2 本を終了する」に変わる
```

同じプロジェクトで何本も開いてしまったときは、最後の項目でまとめて片付けられる。
戻せない操作なので、その場でもう一度だけ聞く作りにしてある。

枠の `×` は枠を閉じるだけで、セッションは生きたまま残る。行の `×` とは別物。

### セッションの状態

| 表示 | 意味 |
|------|------|
| 実行中（緑・点滅） | Claude が作業している。待っていればいい |
| **要対応（琥珀）** | 承認待ちや選択待ち。**自分が動かないと止まったまま** |
| 待機（グレー） | 入力待ち。手が空いている |
| 終了（赤） | プロセスが落ちた |

「実行中だったものが止まった」ときに未読ドットが付く。
ブラウザのタブタイトルにも要対応の件数が出るので、他のウィンドウにいても気づける。

## 他で立てたセッションも見える

ターミナルや Cursor の内蔵ターミナルから `claude` を起動したものも、
「他で動いている」として状態つきで並ぶ。ccdeck を経由していなくても見える。

Claude Code 自身が `~/.claude/sessions/<PID>.json` に状態を書き出しているので、それを読んでいる。

```json
{ "pid": 13893, "cwd": "/Users/xxx", "name": "been10t-bf",
  "kind": "interactive", "status": "waiting", "waitingFor": "input needed" }
```

| Claude Code の status | ccdeck の表示 |
|---|---|
| `busy` | 実行中 |
| `waiting` + `waitingFor: "input needed"` | **要対応** |
| `idle` | 待機 |

画面を解析するより正確なので、外部セッションの状態判定にはこちらを使っている。

### できること・できないこと

**入力は送れない。** そのセッションの擬似端末を持っているのは向こうのターミナルであって、
ccdeck ではないため。横取りすると両方が壊れる。

代わりに行をクリックすると、その tty を抱えている **Terminal.app / iTerm のウィンドウを前面に出す**。
すぐ打てる状態になるので、実用上はこれで足りる。

ただし Cursor や VS Code の内蔵ターミナルで動いているセッションは、
検出と状態表示はできるが前面化はできない（AppleScript で外から操作できないため）。
その場合はトーストでその旨を伝える。

## 構成

```
server/
  index.js     Express + WebSocket。API と静的配信
  sessions.js  PTY の生成・保持と状態判定（このアプリの心臓）
  git.js       git コマンドのラッパ
  projects.js  リポジトリの自動スキャンと「最近使った」の記録
  files.js     ファイル読み書き（プロジェクト外は拒否）
  revive.js    落ちる前に台帳を書き、次の起動で前回の続きを起こす
  external.js  他で立てられたセッションの検出とターミナル前面化
web/
  main.js      画面の状態管理
  term.js      xterm.js の管理
  editor.js    CodeMirror（開いたときだけ読み込む）
docs/
  mobile-sync.md  スマホ同期の仕様と段階
mobile/
  App.tsx       Expo アプリの入口
  src/deck.ts   WebSocket・再接続・状態管理
  src/screens/  ペアリング・一覧・画面・設定
```

### 状態判定の仕組み

Claude Code は**待機中もステータスラインを更新し続ける**ため、「出力がある＝実行中」は成立しない。
そこで出力は再評価のきっかけにだけ使い、状態は headless な xterm に食わせた**実際の画面の中身**から判定している。

- 画面に `esc to interrupt` があれば実行中
- `Do you want …` や `❯ 1.` があれば要対応
- どちらでもなければ待機

### 設定

`~/.ccdeck/config.json` でスキャン対象を変えられる。

```json
{
  "roots": ["/Users/xxx/projects", "/Users/xxx/dev"],
  "maxDepth": 2,
  "pinned": []
}
```

## 実測メモリ（M3 / 24GB）

| | メモリ | プロセス数 |
|---|---|---|
| Cursor（プロジェクト1つ） | 3,148 MB | 19 |
| ccdeck サーバー（3セッション） | 66 MB | 1 |
| メニューバー常駐 | 43 MB | 1 |
| ＋ Chrome ウィンドウ | 約 200 MB | 1 |

`claude` 本体（1本あたり 500〜700MB）はどの方式でも同じだけ要る。
差が出るのは「入れ物」の部分で、ここが約 1/10 になる。
ccdeck はセッションを何本立ててもサーバーは 1 プロセスのまま。

## 開発

```sh
npm run build     # web/ をビルド
npm start         # サーバーを直接起動
```

## スマホから見る（M1）

`mobile/` に Expo 製の iOS / Android アプリがある。同じ Wi-Fi にいるスマホから
セッション一覧と状態を同期し、ccdeck が持つセッションの現在画面を読める。
現段階は **M1（読むだけ）**。キー入力・push 通知・TLS は未実装で、今後の段階と判断は
[docs/mobile-sync.md](docs/mobile-sync.md) にまとめている。

```sh
ccdeck start --lan     # LAN に出す（付けなければ 127.0.0.1 のまま）
cd mobile
npm install
npm start              # Expo の開発サーバー
```

`--lan` を付けたときだけ、左のサイドバーに「スマホ」の節が出る。
そこで 6 桁のコードを発行し、アプリへ待ち受けアドレスと一緒に打ち込むと登録される。
登録トークンは端末の SecureStore に保存され、一覧は WebSocket で自動更新される。
画面を開いている間は 500ms 以上の間隔で現在画面の snapshot だけを受け取り、
バックグラウンドから戻った場合も 512KB の replay を送り直さない。

| | |
|---|---|
| ループバックからの接続 | 今まで通り素通し |
| それ以外 | 端末ごとのトークンが要る。無ければ 401 |
| LAN からのセッション作成 | `agent` は Claude Code / Codex の固定コマンドだけを許可 |
| 端末の登録・失効 | この Mac の画面からのみ |
| LAN からの操作 | `~/.ccdeck/audit.log` に残す（打鍵の中身は残さない） |

トークンは平文で流れる。**信頼できる LAN でだけ使うこと。**
ccdeck は PTY を作れるので、認証なしで LAN に出すのは
その Wi-Fi にいる全員にシェルを配るのと同じになる。
